Your first conversation

  1. 1. Choose a modelPick a provider and model in the toolbar, or use Pi’s default.
  2. 2. Ask a questionType in the prompt card, then click Ask → or press Ctrl/Cmd+Enter.
  3. 3. Explore the answerRead the streaming response, then select a passage or use a + to continue.

Ctrl/Cmd + Enter sends a prompt. Plain Enter adds a newline.

Two ways to branch

Select an excerpt

Drag-select text in an answer or prompt input, then release the mouse. A connected input card opens with the selected text quoted and the cursor ready for your follow-up.

“gradient descent”
Your follow-up: Can you elaborate more on this?

Click a +

Hover over a card to reveal + buttons on its unused sides. Click one to create a connected blank prompt on that side. If every side is connected, a top-right + remains available—there is no connection-count limit.

Both actions create a draft, not an immediate request. Sending it uses the currently selected model and that branch’s ancestral conversation history. Other branches are not included unless you explicitly merge them.

Every question also picks up your tutor notes (the Notes chip at the top-right): standing requests like “use mermaid diagrams for structure” that shape each answer. Global notes apply to all threads; thread notes apply to the current one. Edits affect new questions, not answers already on the canvas.

For an unrelated topic, click ＋ New prompt in the toolbar instead. It creates a separate root conversation.

Bring conversations together

Press S, then click two or more cards to select them—even from unrelated root conversations. Click again to deselect. Press M to open a connected merge draft; originals stay intact and no request starts yet.

Choose Selected cards only to send only source-card content, or Cards + histories to include earlier discussion, with shared history included once. Write instructions such as “Merge only the criticism about X and Y,” then send normally to create a separate answer.

One context switch applies to the whole merge. Its setting is saved and shown as a badge after sending; excluded histories stay excluded when you continue from the answer. Source text is live context, not a frozen snapshot.

Esc or S cancels selection. Selection pauses card controls and dragging; Tab/Space/Enter can toggle selection buttons. The selection bar also works in zen mode.

Only deletion is undoable. Up to 50 deletions are remembered until a thread switch, reload, or Clear; there is no redo yet. Restored streaming answers are stopped, not restarted. While editing, Ctrl/Cmd + Z is left to the input’s native text editing rather than canvas history.

Answers support Markdown headings, lists, links, code blocks, and tables. Mermaid code blocks render as static diagrams after generation finishes. Use Open larger view, scroll to zoom, drag to pan, or use the zoom buttons and Reset to fit. Esc closes the viewer and returns to the card. Diagram source shows the original text; invalid diagrams and unsupported assets/configuration remain readable as source. Rendering stays local and does not change saved Markdown.

Models and extensions

The toolbar separates provider and model selection. pi default delegates the choice to Pi. A listed model still needs account permission and available quota.

At startup, the bridge loads Pi extensions for provider/model registration, then disposes that session. Tutor requests do not reload that entire extension set.

The Extensions accordion is read-only. It shows startup-loaded extensions, their source paths and capabilities, load diagnostics, and tutor extension configuration. Refresh inventory reads the last load snapshot; it does not enable, disable, install, or reload anything.

The Notes chip opens two accordions: Global · all threads (stored once per machine alongside the library) and This thread (saved inside the thread’s .learn file, so it travels on export/import). Both are capped at 4000 characters and applied automatically to every new question.

With web access enabled, tutor requests load only pi-web-access and allow web_search, source_check, fetch_content, and get_search_content. Set LEARNVAS_WEB_ACCESS=0 before starting the bridge to make tutor requests tool-free.

Restart the bridge after changing Pi extension configuration. The inventory is not a list of every installed package.

Saving, privacy, and safety
  • Open Threads to create, switch, rename, trash, or restore a named canvas. Tab and Enter navigate threads; Esc closes the panel. The panel fits narrow screens and hides in zen mode.
  • Cards, text/quotes/model identifiers, connections, explicit sizes/collapse state, per-thread tutor notes, and viewport autosave as .learn files under ~/.learnvas/. Global tutor notes live in a separate tutor-notes.json in the same directory. Browser storage remembers only the last thread and theme. Old browser canvases are not automatically migrated.
  • Switching stops generation, flushes partial answers, saves the outgoing canvas, and resets undo history. Errors/conflicts keep it available: retry saving or enter a new title and save a recovery copy. Invalid library files are preserved with warnings.
  • Saves are debounced by 400 ms; closing or reloading before saving finishes may lose recent changes. Back up library files separately. There is no account sync or collaboration.
  • Import .learn validates UTF-8 content, format, version, graph, and an 8 MiB limit. Confirm the title to add it to the library without switching your canvas. Duplicate IDs require approval of a separate copy; filename collisions require confirmation of a numbered name. Cancel adds nothing. Uploaded originals are never changed.
  • Save and export active stops generation, flushes partial text, saves the latest canvas, and downloads the verified saved document. Saving errors/conflicts produce no download. Files contain the exploration, not credentials, live runtime state, or undo. Text is not redacted—share carefully.
  • Reloading or opening an import does not resume generation. Partial saved answers are marked stopped.
  • New saves use .learn v3. Existing v2 files remain readable and upgrade on their next save; reading alone does not rewrite them. Older builds cannot read v3—keep v2 backups if you need to roll back.
  • Prompts and included branch/merge context go to the chosen model provider. Web queries and URLs may go to external services. Verify important claims and sources.

Tutor sessions are fresh and in-memory: no Pi session files, AGENTS.md context, skills, prompt templates, or built-in file/shell tools are loaded into the tutor session.

This is not a security sandbox. Extensions execute local code with the bridge’s permissions. The bridge binds to loopback and checks trusted browser origins, but does not authenticate local programs. Keep it on a trusted local machine; do not expose it through remote proxies.

Local setup and configuration

You need Node.js 22.19+, pnpm, and a model provider configured in Pi. Learnvas normally reuses credentials from ~/.pi/agent.

pnpm install
# If you need credentials: launch Pi, run /login, then exit.
pnpm exec pi
# For web access, if not already installed:
pnpm exec pi install npm:pi-web-access
just learn

Installing the web extension changes your Pi package configuration. just learn uses Bash and attempts to terminate any process on port 5178 with fuser.

Without just, run pnpm bridge and pnpm dev in separate terminals. For tool-free tutoring, use LEARNVAS_WEB_ACCESS=0 pnpm bridge, or LEARNVAS_WEB_ACCESS=0 just learn with the combined launcher.

Troubleshooting
ProblemTry
No models / authentication errorCheck Pi login, provider environment variables, and the bridge terminal. Returning focus to the app refreshes the model list.
Quota or provider errorCheck account permission, supported models, and credits. Listing a model does not validate a request.
Web requests failCheck the web extension and inventory, or restart with web access disabled to isolate the issue.
API errors / stale backendEnsure the bridge is running on the port configured in Vite. Starting Vite alone does not start the bridge.
Canvas seems emptyOpen Threads and check the library path and any warnings. Old browser canvases are not automatically migrated.
Still in light modeSystem follows your OS. Choose Theme: Dark to override it.

For bug reports, include reproduction steps, Node/pnpm versions, browser details, and relevant errors. Redact keys, tokens, and private prompts.

For contributors

The frontend uses React, TypeScript, Vite, and React Flow. A Node HTTP bridge creates fresh Pi sessions and streams text/tool events back through the chat POST response. No database or separate backend framework is required.

pnpm test
pnpm build

Also check text-selection branching, all continuation sides and the corner fallback, header dragging, resized-card collapse, and both themes. Detailed guides live in the repository’s docs/ directory.
